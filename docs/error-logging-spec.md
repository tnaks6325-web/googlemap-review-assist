# 업무 오류 로그 시스템 사양

## 1. 목적

관리자와 개발자가 오류 코드를 해석하지 않아도 다음 내용을 바로 이해할 수 있도록 한다.

- 어느 업무에서 발생했는가
- 사용자가 무엇을 하던 중이었는가
- 어느 단계에서 멈췄는가
- 확인된 원인 또는 가장 가능성이 높은 원인은 무엇인가
- 사용자와 운영 업무에 어떤 영향이 있는가
- 운영자가 다음으로 무엇을 확인하거나 조치해야 하는가

자연어 설명은 외부 AI 호출 없이 정해진 템플릿과 안전하게 정제한 오류 정보로 생성한다. 오류 기록 기능 자체가 실패해도 원래 사용자 요청은 추가로 실패시키지 않는다.

## 2. 기본 가정

- 오류 로그는 애플리케이션 DB에 저장하고 관리자만 조회할 수 있다.
- 서버의 처리되지 않은 예외, 브라우저의 JavaScript·React hydration 오류, 외부 연동 실패, 배치 작업 실패를 수집한다.
- 입력값 오류, 로그인 정보 불일치, 권한 없음 등 정상적으로 예상되는 일반 4xx 응답은 오류 로그를 남발하지 않는다.
- 반복적인 접근 제한, 비정상 인증 시도처럼 운영 확인이 필요한 보안 신호는 `경고`로 집계할 수 있다.
- 비밀번호, 세션 쿠키, OAuth 토큰, API 키, 계좌번호, 전화번호, 이메일, 요청 본문, 업로드 파일 내용은 저장하지 않는다.
- 오류 로그 보존 기간은 기본 30일로 하고, 정리 작업은 조회 또는 배치 실행 시 하루 한 번만 수행한다.

## 3. 수집 범위

### 서버 공통 오류

Next.js `onRequestError`를 사용해 Route Handler, Server Component, Server Action, 렌더링 과정에서 처리되지 않은 오류를 기록한다.

### 브라우저 오류

Next.js `instrumentation-client.ts`에서 다음 오류를 수집한다.

- `window.error`
- 처리되지 않은 Promise rejection
- React hydration 또는 화면 렌더링 관련 오류

브라우저가 보내는 값은 신뢰하지 않는다. 전용 API에서 길이 제한, 허용 필드 검사, 속도 제한, 민감정보 제거를 다시 수행한다.

### 명시적인 업무 단계 오류

공통 예외 수집만으로는 업무 단계를 알 수 없는 주요 처리에 문맥을 추가한다.

- 관리자 로그인과 세션 확인
- Google Sheets 검사 및 캠페인 반영
- 네이버 플레이스 후보 검색, Place ID 추출 및 저장
- 블로그 참고자료 수집
- 리뷰어 캠페인 배정
- 리뷰 원고 생성
- 리뷰 인증 이미지 업로드, OCR 분석, 제출 및 관리자 승인
- 포인트 적립 및 잔액 정합성 확인
- 정산 요청, 승인 및 지급 완료
- 운영 배치 작업의 실행, 재시도 및 최종 실패
- DB와 외부 API 상태 확인

## 4. 오류 로그 데이터

각 오류는 다음 필드를 가진다.

| 필드 | 설명 |
| --- | --- |
| 심각도 | `경고`, `오류`, `치명적` |
| 발생 위치 | 서버 API, 서버 화면, 브라우저, 배치, 외부 연동 |
| 업무 | 예: 캠페인 가져오기, 네이버 장소 연결, 원고 생성 |
| 단계 | 예: Google Sheets 읽기, 후보 페이지 열기, Place ID 저장 |
| 제목 | 한 문장으로 요약한 자연어 제목 |
| 상황 설명 | 사용자가 무엇을 하던 중이었는지 설명 |
| 원인 설명 | 확인된 원인 또는 안전하게 판단 가능한 원인 |
| 영향 | 어떤 업무가 완료되지 않았는지 설명 |
| 권장 조치 | 운영자가 확인할 다음 행동 |
| 오류 코드 | 검색과 분류를 위한 안정적인 내부 코드 |
| 기술 정보 | 민감정보가 제거된 오류명·메시지·Next.js digest |
| 요청 정보 | 쿼리 문자열을 제거한 경로, HTTP 방식, 요청 추적 ID |
| 대상 정보 | 캠페인·배정·정산 등의 내부 ID와 대상 종류. 개인정보는 제외 |
| 상태 | `미확인`, `확인 완료` |
| 발생 횟수 | 같은 오류가 반복된 횟수 |
| 최초·최근 발생 시각 | 반복 오류의 시작과 마지막 시각 |

같은 오류 코드, 업무, 단계, 경로, 대상 ID로 만든 지문이 같으면 새 행을 계속 만들지 않고 발생 횟수와 최근 발생 시각을 갱신한다. 확인 완료된 오류가 다시 발생하면 다시 `미확인` 상태로 전환한다.

## 5. 자연어 로그 규칙

자연어 로그는 다음 형태를 유지한다.

> 캠페인 가져오기 업무에서 Google Sheets 내용을 읽는 단계가 완료되지 않았습니다. Google 인증 정보가 없거나 만료되어 원격 문서에 접근하지 못한 것이 원인입니다. 새 캠페인 정보가 반영되지 않았으며 기존 캠페인에는 변화가 없습니다. Google Sheets 연결 설정과 서비스 계정 권한을 확인한 뒤 다시 실행해 주세요.

- 내부 예외 메시지를 그대로 사용자 설명으로 사용하지 않는다.
- 원인이 확정되지 않으면 단정하지 않고 “가능성이 있습니다”라고 표현한다.
- 기술 정보는 별도 영역에 두고 자연어 설명과 분리한다.
- 알려진 오류는 코드별 템플릿을 사용한다.
- 알려지지 않은 오류는 업무·단계 문맥과 안전하게 정제한 오류 유형으로 일반 설명을 만든다.

## 6. 보안과 안정성

- 필드별 허용 목록을 사용하며 임의의 요청 객체나 오류 객체 전체를 직렬화하지 않는다.
- 토큰, 쿠키, Authorization 헤더, URL 쿼리, 비밀번호, 전화번호, 이메일, 계좌번호 패턴을 마스킹한다.
- 브라우저 로그 수집 API에는 IP·세션 기준 속도 제한과 최대 본문 크기를 적용한다.
- 로그 기록 함수는 내부에서 모든 예외를 흡수하고 안전하게 정제한 한 줄만 서버 콘솔에 대체 기록한다.
- 사용자에게 반환하는 기존 오류 응답 형식과 상태 코드는 변경하지 않는다.
- 관리자 세션이 없으면 오류 목록·상세·상태 변경 API에 접근할 수 없다.

## 7. 관리자 화면

관리자 메뉴에 `오류 로그`를 추가한다.

- 미확인 오류, 오늘 발생 오류, 치명적 오류 수를 요약한다.
- 최근 발생 순으로 목록을 표시한다.
- 심각도, 발생 위치, 업무, 상태로 필터링한다.
- 각 항목에서 자연어 상황·원인·영향·권장 조치와 기술 정보를 구분해 보여준다.
- 운영자가 `확인 완료`로 표시할 수 있다.
- 개인정보나 인증 정보는 화면과 응답에 포함하지 않는다.

## 8. 구현 경계

포함:

- DB 모델과 저장·중복 집계·조회·상태 변경
- 서버 및 브라우저 공통 수집
- 주요 업무 흐름의 단계 문맥 연결
- 관리자 조회 화면
- 30일 보존 정리
- 마스킹, 길이 제한, 속도 제한

제외:

- 이메일, Slack, 문자 등 외부 알림
- 외부 오류 추적 SaaS 도입
- 로그 원문 파일이나 업로드 이미지 저장
- 오류 원인의 AI 자동 추론
- 일반 사용자 입력 실수의 전수 저장

## 9. 테스트와 검증 명령

- 자연어 생성, 마스킹, 중복 지문, 심각도 분류 단위 테스트
- SQLite 테스트 DB를 이용한 저장·중복 집계·확인 완료 통합 테스트
- 브라우저 로그 API 인증·속도 제한·본문 제한 테스트
- 주요 업무 오류가 올바른 업무·단계 문맥으로 기록되는 테스트
- 관리자만 목록을 볼 수 있는 권한 테스트
- `npm test`
- `npm run lint`
- `npm run build`
- 관리자와 리뷰어의 주요 흐름을 실제 브라우저에서 실행하고 콘솔·네트워크·오류 로그 화면 확인

## 10. 완료 기준

- 처리되지 않은 서버 오류와 브라우저 오류가 DB에 기록된다.
- 지정한 주요 업무 실패가 업무·단계·원인·영향·조치 문장으로 기록된다.
- 민감정보가 로그 DB와 관리자 응답에 남지 않는다.
- 같은 오류는 하나의 항목으로 집계되고 발생 횟수가 증가한다.
- 관리자가 오류를 필터링하고 확인 완료 처리할 수 있다.
- 오류 로거 장애가 원래 서비스 요청을 실패시키지 않는다.
- 전체 테스트, lint, production build가 통과한다.

## 11. 승인할 기본값

- 로그 보존: 30일
- 반복 오류: 동일 지문으로 누적 집계
- 일반 4xx 사용자 실수: 저장하지 않음
- 브라우저 오류: 익명으로 수집하되 경로와 브라우저 종류만 저장
- 외부 알림: 이번 범위에서는 제외
