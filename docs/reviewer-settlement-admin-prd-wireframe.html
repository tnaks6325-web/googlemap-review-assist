리뷰어 정산 신청과 관리자 리뷰어 관리

리뷰어가 최초 1회 정산 계좌를 등록한 뒤 포인트 정산을 신청하고, 관리자가 엑셀 다운로드 후 수동 이체 및 정산완료 처리를 하는 운영 흐름입니다.

구분요구사항완료 기준
리뷰어 최초 1회 은행, 계좌번호, 예금주를 등록하고 정산 가능 포인트 안에서 정산 신청 최소 3,000원, 1,000원 단위만 신청 가능. 요청 후 사용 가능 잔액은 차감되고 정산대기 금액으로 표시
관리자 리뷰어 목록, 적립금 현황, 정산 요청 목록을 한 화면에서 확인 필터, 검색, 상태별 카운트, 상세 보기 제공
정산 파일 REQUESTED 상태 정산건을 은행 이체용 엑셀로 다운로드 정산ID, 연락처, 은행, 계좌번호, 예금주, 금액 포함
완료 처리 관리자가 인터넷뱅킹 이체 후 선택 건을 정산완료 처리 정산 상태 PAID, 리뷰어 알림 생성, 정산대기 금액 0원 반영
보안 계좌정보는 민감정보로 취급하고 다운로드/완료 처리는 관리자만 가능 권한 확인, 감사로그, 계좌 마스킹, 완료 처리 멱등성 보장

상태와 금액 정의

리뷰어 지갑 표시

  • 정산 가능 금액: 아직 정산 요청하지 않은 출금 가능 포인트
  • 정산 대기 금액: 신청 후 관리자 이체 대기 중인 금액
  • 누적 정산 완료: PAID 처리된 전체 금액
  • 정산 요청 시 정산 가능 금액은 즉시 차감되고 정산 대기 금액으로 이동

Settlement 상태

  • REQUESTED 리뷰어 신청 완료, 관리자 이체 대기
  • PAID 관리자가 실제 이체 후 완료 처리
  • REJECTED 계좌 오류 등으로 반려, 금액은 리뷰어 지갑으로 복원
  • APPROVED 중간 상태는 MVP에서 생략하고 수동 이체 후 PAID로 직접 처리

유저플로우

리뷰어 정산 신청

1. 내 적립금

정산 가능 금액과 대기 금액을 확인한다.

2. 계좌 확인

최초 1회 등록한 은행, 계좌번호, 예금주를 확인한다.

3. 금액 입력

최소 3,000원, 1,000원 단위, 보유 가능액을 검증한다.

4. 신청 완료

금액을 보류하고 REQUESTED 상태를 만든다.

5. 알림 확인

관리자 PAID 처리 후 정산완료 알림을 본다.

관리자 정산 운영

1. 리뷰어 관리

리뷰어별 잔액, 참여, 정산 상태를 확인한다.

2. 정산 대기 필터

REQUESTED 목록과 합계 금액을 확인한다.

3. 엑셀 다운로드

은행 이체용 파일을 내려받고 다운로드 이력을 남긴다.

4. 인터넷뱅킹 이체

관리자가 외부 은행 사이트에서 직접 이체한다.

5. 정산완료 처리

선택 건 PAID 처리, 알림 생성, 대기 금액 제거.

API / 데이터 설계

Reviewer API

  • GET /api/me/settlement-summary: 잔액, 대기금액, 완료금액, 계좌 등록 여부
  • PUT /api/me/payout-account: 최초 1회 은행, 계좌번호, 예금주 등록. 수정은 별도 재확인 후 허용
  • POST /api/settlements: 정산 신청, 최소 3,000원 및 1,000원 단위 검증, 등록 계좌 스냅샷 저장
  • GET /api/settlements: 본인 정산 내역
  • GET /api/notifications: 정산완료/반려 알림

Admin API

  • GET /api/admin/reviewers: 리뷰어 목록, 잔액, 참여, 정산 요약
  • GET /api/admin/settlements?status=REQUESTED: 정산 대기 목록
  • GET /api/admin/settlements/export: 이체용 엑셀/CSV 다운로드
  • POST /api/admin/settlements/mark-paid: 여러 정산건 일괄 PAID 처리
  • POST /api/admin/settlements/[id]: 단건 PAID 또는 REJECTED 처리

보안/운영 기준

계좌정보

  • 리뷰어는 정산받을 계좌를 최초 1회 등록하고 이후 정산 신청 때 재사용
  • 계좌 변경은 별도 수정 버튼에서만 가능하며 변경 이력을 남김
  • 화면 기본 표시는 은행명, 예금주, 끝 4자리만 노출
  • 엑셀 다운로드에는 이체를 위해 전체 계좌번호 포함
  • 다운로드는 관리자 세션과 감사로그 필수

중복 지급 방지

  • PAID 처리는 REQUESTED 상태에서만 허용
  • 일괄 완료 API는 이미 처리된 건을 건너뛰거나 409 반환
  • 금액 원장은 append-only로 유지

운영 예외

  • 계좌 오류 시 REJECTED 처리 및 잔액 복원
  • 다운로드 후 완료 미처리 건은 관리자 상단에 경고
  • 정산 완료 알림은 앱 내부 알림 우선, SMS는 후속
