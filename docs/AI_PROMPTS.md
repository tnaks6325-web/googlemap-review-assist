# AI 초안 생성 — 프롬프트 설계 상세

> 관련: [API_SPEC.md](API_SPEC.md) `POST /api/drafts` · [PRD.md](PRD.md) C2 · [DATA_MODEL.md](DATA_MODEL.md) `AiDraft`
> 모델: `claude-opus-4-8` (품질) / `claude-haiku-4-5` (비용·지연 우선). 상세는 `/claude-api` 참조.

---

## 0. 설계 원칙 (컴플라이언스 C2)

> **AI는 고객의 경험을 "창작"하지 않는다. 고객이 제출한 사실을 "문장으로 다듬을" 뿐이다.**

- **유일한 사실 출처** = 고객이 설문(별점/선택메뉴/한 줄 소감)에서 직접 제출한 내용.
- 메뉴명·상호는 *표기 정확도* 보조용. 고객이 선택하지 않은 메뉴·경험·수치·감정을 새로 만들지 않는다.
- 별점/소감과 모순되는 미사여구 금지(예: 3점인데 "인생 맛집").
- 광고성·과장·정형화된 홍보 문구 회피(humanizer 관점).
- 출력은 **초안일 뿐**, 고객이 자유 수정/폐기/미게시 가능(C3).

---

## 1. 입력 컨텍스트 (서버가 구성)

`POST /api/drafts`가 `feedbackId`로 아래를 조립한다:

```json
{
  "businessName": "○○식당",
  "rating": 4,
  "selectedMenus": ["김치찌개", "계란말이"],
  "comment": "반찬이 깔끔하고 양이 많아요",
  "menuCatalog": ["김치찌개","제육볶음","계란말이","된장국","공기밥"],
  "locale": "ko-KR"
}
```
- `menuCatalog`는 표기 교정용(고객이 "계란말이"를 "계란"으로 적어도 정식명 보정). **선택 외 메뉴 추가 금지**.
- `comment`가 비면, 별점+선택메뉴만으로 짧게 생성(없는 내용 보충 금지).

---

## 2. 시스템 프롬프트 (초안)

```
당신은 사용자가 직접 작성하려는 가게 리뷰의 '초안'을 다듬어 주는 보조 작가입니다.
사용자가 실제로 제출한 정보만 사용해 자연스러운 한국어 리뷰 문장으로 정리하세요.

[반드시 지킬 것]
1. 사용자가 제출한 별점·선택 메뉴·소감에 들어있는 사실만 사용한다.
2. 사용자가 언급하지 않은 메뉴, 경험, 직원, 분위기, 가격, 재방문 의사 등을
   새로 지어내지 않는다.
3. 메뉴 이름은 제공된 메뉴 목록(menuCatalog) 표기에 맞춰 교정하되,
   목록에 있어도 사용자가 선택하지 않은 메뉴는 넣지 않는다.
4. 별점과 소감의 톤에 맞춘다. (낮은 별점에 과한 칭찬 금지, 높은 별점에 과한 비난 금지)
5. 광고처럼 들리는 정형 문구·과장·이모지 남발을 피하고, 사람이 쓴 듯 담백하게.
6. 1~3문장, 한국어 구어체. 별점을 숫자로 다시 적지 않는다.

출력: 리뷰 본문 텍스트만. 설명·머리말·따옴표 없이.
```

## 3. 유저 프롬프트 (템플릿)

```
가게: {businessName}
별점: {rating}/5
좋았다고 선택한 메뉴: {selectedMenus | "없음"}
한 줄 소감: {comment | "(없음)"}
(참고용 메뉴 표기 목록: {menuCatalog})

위 정보만으로 리뷰 초안을 작성해 줘.
```

## 4. 호출 파라미터

| 항목 | 값 | 비고 |
|---|---|---|
| max_tokens | ~300 | 1~3문장이면 충분 |
| temperature | 0.7 | 자연스러움 ↔ 일탈 방지 균형 |
| 재생성 | 동일 입력 + "조금 다른 표현으로" 지시 | 버전 누적(`AiDraft.version`) |
| 타임아웃 | p95 6s, 초과 시 502 | 적립·설문 무관(독립) |

## 5. 출력 후처리 / 가드

생성 후 서버에서 경량 검증:
- **메뉴 누출 검사**: 출력에 등장한 메뉴명이 `selectedMenus`에 없고 `menuCatalog`에만 있으면 경고/재생성.
- **길이·정형구 필터**: 과도한 길이, "강추합니다", "JMT" 류 정형 광고문구 페널티.
- **별점-톤 정합**: 별점 ≤2인데 긍정 일색이면 재생성 트리거(휴리스틱).
- 실패/부적합 시 사용자에겐 "직접 작성도 가능" 안내, **적립 불변**.

## 6. 예시

입력: rating=4, menus=["김치찌개","계란말이"], comment="반찬이 깔끔하고 양이 많아요"
바람직한 초안:
> 김치찌개랑 계란말이를 먹었는데 반찬이 깔끔하고 양도 넉넉해서 만족스러웠어요. 다음에 또 들를 것 같네요.

❌ 금지 예(창작): "사장님이 정말 친절하시고 주차도 편해요" — 고객이 말한 적 없음(C2 위반).

## 6b. 영수증 OCR 프로바이더 (참고)

리뷰 초안과 별개로, 영수증 검증용 OCR은 `lib/ocr`에 추상화되어 있다.
- 개발: 스텁(`mockText` 정규식 파싱).
- 운영: `OCR_PROVIDER=vision` + `GOOGLE_VISION_API_KEY` → Google Vision TEXT_DETECTION REST.
- 파서(`lib/ocr/parse.ts`)는 두 프로바이더가 공유. 검증 판정은 `lib/domain/receipt-verify.ts`(승인번호·금액·가맹점·신뢰도 fail-closed)에서 수행.
- 신뢰도: Vision은 페이지 confidence 평균 사용(없으면 0.8). 스텁은 구조적 완성도(필드수/4).

## 7. 로깅 / 감사

- `AiDraft`에 입력 스냅샷 해시 + 모델·버전 기록(재현성).
- 개인정보(소감) 보관 정책은 PRD NFR(보안) 따름.

## 8. 캠페인 원고 다양성 v4

- 운영자형 캠페인은 `review-diversity-v4`의 25개 스타일 슬롯과 명사형을 제외한 한국어 종결 및 `~`·`!!`·`!!!` 문장부호 프로필을 사용한다.
- 플레이스·외부 리뷰·블로그 자료는 출처가 연결된 사실 카드로 추출하며, 추출 즉시 원고 근거로 자동 적용된다.
- Gemini 응답은 `reviewText`, `styleId`, `evidenceIds`, `promptVersion` 구조로 받고 서버에서 승인 근거·길이·업종 금지어·상호/주소·캠페인 내 유사도를 다시 검증한다.
- 정규화 문자 3-gram Dice 유사도 `0.72` 이상, 동일 도입 10자, 동일 연속 문구 12자 이상은 보정 재생성 대상이다.
- 운영 원고 적용은 `REVIEW_DRAFT_V2_ENABLED=true`일 때만 활성화한다. 관리자 25개 미리보기는 실제 배정 원고를 저장하지 않는다.
