## 1. 개요 (Vision)

소상공인의 구글맵 노출/신뢰도를 **진짜 방문 고객의 자발적 리뷰**로 키운다. 고객이 겪는 "무엇을 쓸지 막막함 / 과정의 번거로움"을 제거하되, **리뷰 내용은 고객 본인의 경험**을 AI가 문장으로 다듬는 방식으로 합법성을 유지한다.

한 줄 정의: **영수증으로 검증된 실고객이, 클릭형 설문으로 자기 경험을 남기면, AI가 그 경험을 자연스러운 리뷰 초안으로 다듬어 주는 도구.**

## 2. 해결하려는 문제

| 대상 | Pain Point |
|---|---|
| 사장님 | 리뷰 수가 적어 구글맵 노출/신뢰가 낮음. 직접 리뷰를 유도할 합법적 수단이 없음 |
| 고객 | 좋게 먹고도 "리뷰 쓰기 귀찮음/뭐라 쓸지 모름". 작성 동기 부족 |
| 양측 | 기존 대행은 가짜 리뷰 → 적발 시 업체가 더 큰 제재를 받음 |

## 3. 페르소나

- **사장님(Owner)**: 자영업자. 모바일/PC 웹으로 매장·메뉴 등록, QR 비치, 통계 확인. 결제는 구독.
- **고객(Reviewer)**: 매장 방문객. 모바일 웹으로 QR 진입, 앱 설치 없이 클릭 위주로 참여. 적립금에 관심.
- **(후속) 관리자(Admin)**: 어뷰징 모니터링·정산 승인.

## 4. 목표 & 성공지표 (Metrics)

| 구분 | 지표 | 초기 목표 |
|---|---|---|
| 핵심 | 영수증 인증 → 설문 완료 전환율 | ≥ 60% |
| 핵심 | 설문 완료 → 공개 리뷰 게시(자율) 전환율 | 측정·관찰 (강제 아님) |
| 사업 | 매장당 월 비공개 피드백 수 | 관찰 |
| 신뢰 | 어뷰징(영수증 중복/다계정) 차단율 | ≥ 99% |
| 컴플라이언스 | 보상-게시 분리 위반 건수 | **0 (불변)** |

> 주의: "매장당 하루 N건"은 **목표 지표로 설정하지 않는다**(할당량 = 어뷰징 유인). 실제 방문 건수가 자연 상한.

## 6. 비기능 요구사항 (NFR)

- **성능**: 고객 플로우 주요 화면 LCP < 2.5s(모바일 3G 기준 고려). AI 초안 생성 p95 < 6s.
- **보안**: 개인정보 최소 수집(휴대폰), 영수증 이미지 접근 통제, OTP 레이트리밋.
- **확장성**: 멀티 매장·멀티 캠페인. 원장은 append-only로 무한 증가 대비 파티셔닝 여지.
- **가용성**: AI API 장애 시 설문/적립은 정상 동작(초안만 실패 처리, 적립은 보장).
- **국제화**: 1차 한국어. 문구 i18n 구조만 분리.

## 7. 범위 (Scope)

**In (MVP, P0)**: 사장님 가입/매장·메뉴/캠페인, 고객 OTP/영수증 코드 인증/설문/EARN 적립/AI 초안/딥링크, 적립금 조회, 기본 통계, 무결성(중복·멱등·원장).

**Out (이번 아님)**: OCR 자동검증, 정산 실지급(PG), 구독 결제, 관리자 백오피스, 고급 통계/세그먼트, 푸시·네이티브 앱.

## 8. 가정 & 제약 (Assumptions)

- 구글 리뷰는 **고객이 직접** 구글맵 앱/웹에서 게시한다(우리가 대신 게시 X — 정책·기술 모두).
- 구글 Place 연결은 식별·딥링크 용도. 리뷰 자동 게시 API는 사용하지 않는다.
- 적립금의 실화폐 정산은 별도 법무·세무 검토 후 P1에서 활성화.

## 9. 리스크 & 컴플라이언스 (불변 조건)

> ARCHITECTURE.md §2의 5개 invariant를 본 PRD의 수용 기준으로 승격한다.

| # | 불변 조건 | 검증 방법 |
|---|---|---|
| C1 | 보상 트리거는 `feedback.submitted`뿐. `review.posted`에 보상 연결 금지 | 스키마상 EARN은 feedback_id만 참조 가능 |
| C2 | AI는 고객 답변·메뉴명 외 사실을 생성하지 않음 | 프롬프트 제약 + 출력 검수 가이드 |
| C3 | 공개 게시는 자율(강제·자동 게시 없음) | 플로우상 게시 버튼은 외부 딥링크뿐 |
| C4 | 보상-게시 근접 기능 도입 시 경제적 이해관계 표시 자동 삽입 | 현재 분리되어 불필요, 변경 시 게이트 |
| C5 | 할당량 미구현. 영수증 1건 1적립 | dedupe_hash + idempotency_key |

## 10. 릴리스 단계

1. **M1 (P0)**: 사장님 온보딩 + 고객 핵심 루프(인증→설문→EARN→초안→딥링크) + 적립금 조회.
2. **M2 (P1)**: OCR, 정산, 구독 결제, 전환율 지표.
3. **M3 (P2)**: 관리자, 고급 분석, 어뷰징 자동탐지.

## 11. 수용 기준 (Acceptance, 발췌)

- 동일 영수증 코드로 두 번 제출 시 두 번째는 거부되고 EARN은 1회만 기록된다. (FR-S1, FR-S2)
- 설문 제출 트랜잭션이 실패하면 EARN도 롤백된다(원자성). (FR-S3)
- AI 초안 생성이 실패해도 적립과 설문 데이터는 보존된다. (NFR 가용성)
- 고객이 게시하지 않아도 적립금은 그대로 유지된다. (C1, C3)
