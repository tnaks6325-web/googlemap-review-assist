# UI/UX 디자인 시스템 & CTA 전략 (토스 스타일)

> 관련: [WIREFRAMES.md](WIREFRAMES.md) · [USER_FLOWS.md](USER_FLOWS.md)
> 컨셉: **토스(Toss) 스타일** — 무채색 베이스 + 블루 포인트 1색, 큰 타이포·넉넉한 여백, 한 화면 한 액션, 하단 고정 단일 CTA로 다음 행동을 끊김 없이 유도. **보라톤(purple/violet) 일절 사용 안 함.**

---

## 1. 디자인 원칙 (Toss-like)

1. **한 화면, 한 결정.** 화면마다 주(主) 행동 1개. 부가 행동은 위계를 낮춘다.
2. **하단 고정 Primary CTA.** 화면 맨 아래 풀폭 버튼이 항상 "다음 한 걸음"을 가리킨다.
3. **숫자·핵심을 크게.** 적립 포인트·별점·잔액 등 핵심 값은 크고 굵게.
4. **담백한 무채색 + 포인트 1색.** 배경/카드는 그레이·화이트, 강조는 블루 하나로 통일.
5. **친근한 짧은 존댓말 카피.** "~해요" 체, 동사 중심, 이득을 함께.
6. **진행감 제공.** 단계 인디케이터로 "곧 끝남"을 체감시켜 이탈 방지.

---

## 2. 컬러 토큰 (보라 배제)

```
/* Primary — Toss 느낌의 블루 (보라 X) */
--blue-500:  #3182F6;   /* Primary action */
--blue-600:  #2272EB;   /* pressed */
--blue-50:   #E8F3FF;   /* tint 배경 */

/* Neutral (무채색 베이스) */
--bg:        #F2F4F6;   /* 앱 배경 */
--surface:   #FFFFFF;   /* 카드 */
--line:      #E5E8EB;   /* 구분선 */
--text-strong: #191F28; /* 제목 */
--text:      #333D4B;   /* 본문 */
--text-sub:  #4E5968;   /* 보조 */
--text-weak: #8B95A1;   /* 캡션/placeholder */

/* Semantic */
--green-500: #00C896;   /* 성공/적립 */
--red-500:   #F04452;   /* 오류/경고 */
--yellow-400:#FFC83C;   /* 별점 */
```
- **금지**: purple/violet 계열(#7C3AED, #8B5CF6 등) 전면 사용 안 함.
- 강조는 항상 `--blue-500` 하나로 수렴. 그라데이션은 같은 블루 계열 내에서만 절제 사용.

## 3. 타이포그래피

- 서체: **Pretendard**(한글 가독·토스 톤). 폴백 system-ui.

| 토큰 | 크기/굵기 | 용도 |
|---|---|---|
| Display | 28 / 700 | 적립액·잔액 등 핵심 숫자 |
| Title | 22 / 700 | 화면 제목("오늘 방문 어떠셨나요?") |
| Body | 16 / 500 | 본문·옵션 |
| Label | 15 / 600 | 버튼·칩 |
| Caption | 13 / 500 | 보조 안내 |

- 줄간격 1.4~1.5, 자간 -0.2 (한글 또렷하게). 숫자는 tabular.

---

## 4. 컴포넌트 규격

- **Primary 버튼**: 높이 56, radius 14, `--blue-500` 배경 / 흰 글씨, 풀폭. press 시 `--blue-600` + scale 0.98.
- **Secondary 버튼**: 흰 배경 + `--line` 테두리 또는 `--blue-50` tint, 텍스트 `--blue-500`.
- **Text 버튼**: 무배경, 부가/회피 동선("그냥 마치기").
- **카드**: `--surface`, radius 16, 그림자 약하게(0 1 2 rgba(0,0,0,.04)).
- **칩(메뉴 선택)**: 비선택 = 흰+테두리, 선택 = `--blue-50` 배경 + `--blue-500` 글씨/테두리, 좌측 체크.
- **입력 필드**: 높이 52, radius 12, focus 시 `--blue-500` 보더.
- **별점**: `--yellow-400`, 탭 영역 48px+.
- **진행 인디케이터**: 상단 얇은 바 또는 "2/4" 라벨.
- **금액 표시**: Display 타이포 + 단위 "P"는 한 단계 작게.
- **토스트/바텀시트**: 토스 식 부드러운 등장, 하단에서 슬라이드.

## 5. CTA 전략 — 행동유도 체인

핵심: **각 화면의 Primary CTA가 곧 다음 화면의 시작**이 되도록 한 줄로 연결. 부가/회피 동선은 Secondary·Text로 위계를 낮춰 메인 흐름을 흐리지 않는다.

| 화면 | Primary CTA (블루·하단 고정) | Secondary/Text | 이어지는 행동 |
|---|---|---|---|
| R0 진입 | **시작하기** | — | → 인증 |
| R1 OTP | **인증번호 받기** → **확인** | (재발송: 비활성/타이머) | → 영수증 |
| R2 영수증 | **확인** | (P1) 사진으로 인증 | → 설문 |
| R3a 별점 | **다음** (별점 선택 시 활성화) | — | → 메뉴 |
| R3b 메뉴 | **다음** | 건너뛰기(Text) | → 소감 |
| R3c 소감 | **제출하고 적립받기** 💙 | — | → 적립 완료(보상 확정) |
| R4 적립완료 | **리뷰 초안 받기** | 그냥 마치기(Text) | → 초안(선택) |
| R5 초안 | **복사하기** | 다시 생성(Secondary) | → 게시 안내(선택) |
| R6 게시 | **구글맵에서 리뷰 쓰기 →** | 나중에 하기(Text) | → 외부(자율) |
| R7 지갑 | (P1) **정산 요청** | — | — |

### CTA 카피 원칙
- **동사 + 이득**을 한 문장에: "제출하고 적립받기"(행동+보상), "리뷰 초안 받기"(행동+편익).
- **진행감**: "다음", "확인" 등 짧고 명료. 마지막 적립 단계만 보상을 명시.
- **위계로 컴플라이언스 보호**: 적립은 R3c에서 끝나고, R4 이후의 초안·게시는 **Secondary/Text**로 낮춰 "게시해야 적립"이라는 오해를 차단(C1/C3). 게시 CTA(R6)는 항상 **외부 이동 + "나중에 하기"** 동선을 함께 둔다.
- **비활성 → 활성**: 선택 전 CTA는 비활성(회색), 조건 충족 시 블루로 살아나 다음 행동을 시각적으로 당긴다.

---

## 6. 모션 / 피드백

- **적립 완료(R4)**: 체크 아이콘 팝 + "+500P" 카운트업(0→500), 잔액 갱신 슬라이드. 토스의 "금액이 살아 움직이는" 느낌.
- **버튼**: press scale 0.98, 로딩 시 스피너 인라인(텍스트 유지).
- **화면 전환**: 가로 슬라이드(다음/이전), 200~250ms ease-out.
- **칩 선택**: 체크 인 + 살짝 바운스.

---

## 7. 접근성 / 모바일

- 대비: 텍스트/배경 WCAG AA. 블루 위 흰 글씨 대비 확보.
- 터치 타겟 ≥ 48×48. 하단 CTA는 safe-area inset 고려.
- 별점·칩에 스크린리더 라벨. 색만으로 상태 표현 금지(아이콘 병행).
- 한 손 조작: 주요 액션을 하단에 배치.

---

## 8. 사장님(웹) 적용

- 동일 토큰·블루 포인트. 데이터는 카드 + 큰 숫자(피드백 수/평균별점)로 토스 대시보드 톤.
- 차트는 무채색 + 블루 강조 1색. 표는 여백 넉넉히.
- 주요 액션(캠페인 발급 등)은 화면당 1개 Primary로 명확히.

---

## 9. 구현 메모

- 토큰은 CSS 변수 + Tailwind theme로 매핑(`bg`, `surface`, `blue-500` 등). 보라 계열 팔레트는 테마에서 제외.
- 공통 컴포넌트(Button/Chip/Field/AmountText/StepBar) 우선 구축 → 화면 조립.
- Pretendard 웹폰트 로드. 다크모드는 P1(토큰만 분리 준비).
